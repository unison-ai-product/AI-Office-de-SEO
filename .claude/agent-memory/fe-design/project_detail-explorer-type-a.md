型A（メトリクスグリッド）共通化＋記事版ページの設計相談への推奨（2026-07-09）:

1. サイドバー（212px・スクロール禁止）= 2グループ（同種Top3＋現在ページ / 跨ぎ1〜2件）＋理由サブ行1本（9.5px mono・チップ禁止=折返しで行高が暴れる）。合計6行が物理上限（最小検収窓1024x700で余白250px考慮の実測340px）。件数はビューポートで変えない。
2. kw↔記事クロス動線は許可。分離グループ＋アイコン＋部屋アクセント色変化（既存aosSweep/SECTIONヘッダー）で種別宣言。サイドバー=移動 / カード5関連チップ=データ、の役割分担。
3. 基本データカードは3x2=6stat。上段=MARKET(DataForSEO: 検索数/難易度/CPC)・下段=PERFORMANCE(GSC28日: クリック/表示回数/CTR)の来歴段分け。平均掲載順位はトレンドカードに一本化（重複禁止）、割当ステータスはヘッダーチップへ。数値18-19px。
4. 生成22ページの温度差は隠さず「注意配分」として構造化: ヘッダーバッジ最大1個（平常は無印）/分析カードに「詳細分析|自動監視中」深度チップ＋数値差し込み定型文/CTAは注目=青グラデ・平常=ghost弱アクション。
5. P0: relatedOf(targetId)単一導出関数を先に仕様化（表示面ごとの別ロジック禁止=REQ-AOUI-01再発防止）。欠損状態の型A版プレースホルダを6カード分先に定義。P2: #5B6B84はダーク上3.5:1でAA未達→#7E8DA9以上。

**Why:** DataForSEO+GSC実API逆引きが前提のため、来歴・鮮度・欠損の設計が説得力の核。スクロール禁止(§6.6)と212px幅がすべての件数/チップ判断を規定する。
**How to apply:** 型A共通レンダラや関連度サイドバーの実装レビュー時にこの推奨と突合する。
