# Design.md 追補 — プロトで確定したデザイン規約（v3.7.17 提案）

> 本追補はプロトレビューでの指摘「ユーザー画面に開発用語が表に出すぎ」を受けた恒久規約。
> リポジトリ側 `Design.md` §6（ビジュアルデザイン言語）の次に §6.5 として取り込むこと。
> 根拠: REQ-NAV-01（内部用語の第一階層・一般画面への非表示）を全画面・全文言へ拡張する。

## §6.5 UI表示言語規約 — 内部用語・開発用語をユーザーに見せない

### 原則

1. **仕様のIDや工程記号はUIに出さない。** REQ-*、AC-*、S1〜S7、W1〜W9、A0〜A8、PT-*、Stage などの管理番号は、ドキュメントとコード内のみ。UIラベル・注記・トースト・通知文に含めない。
2. **内部アーキテクチャ用語を出さない。** Pack / Ticket / Snapshot / Source Extract / Dynamic Post Schema / GSC Data Mart / イベントエンベロープ / Executor / Orchestrator / レーン(lane) / hard gate / advisory / fail-close / full_auto / Kill Switch（英字表記）は禁止。
3. **状態機械はユーザー語彙に翻訳する。** 「13状態＝実務工程9＋強制ゲート4」→「全13工程」。ゲート名は動作で言う: Intake→受付チェック、Quality Gate→品質チェック、Preview承認→公開前承認、Cleanup→仕上げ。
4. **英語ログ形式のイベント文を出さない。** `job.stage_changed` のような event_type はUIでは日本語の文に変換する（例:「J-1024 品質チェック合格 → 承認待ちへ」）。ジョブID（J-xxxx）は照会用として表示可。
5. **安全機構は効果で説明する。** 「fail-close」→「安全のため自動公開を停止しました」、「hard gate不合格」→「品質チェックで必須項目が不合格のため保留」。
6. **SEO業界用語は可・製品内部用語は不可。** intent / YMYL / CTR / SERP など施策判断に必要な業界用語は表示してよい（初出はなるべく日本語補足）。製品の実装都合の語は不可。

### 運用

- 新しい画面・文言を追加するときは、この対訳表に照らしてからマージする。表にない内部用語が必要になったら、**先に対訳を追加**する。
- プロト検証用のコントロール（表示状態トグル等）は「（検証用）」ラベルを付け、内部要求IDは書かない。
- 例外: 開発管理者コンソール（ADM-S*）は開発者向けのため本規約の対象外。

## 追補2 — 通常SaaSビューのシェル規約

- 通常ビューは**アプリシェル型**とする: サイドメニューは画面左端に全高で固定（中央寄せのページ型レイアウト禁止）。ロゴはサイドメニュー上部、ユーザー情報は下部。
- ヘッダーはコンテンツ列の上に固定（56px）。サイト切替・ジョブインジケータ・通知センター・**グローバル検索（REQ-PRODUCT-15）**を常設（第一階層7項目には数えない）。ヘルプ（専用サイト）と公開ステータスページへの導線も常設グローバル要素とする（REQ-PRODUCT-16）。
- 画面内の第二階層はタブ、第三階層（個別レコードの詳細・編集）はパネル/ドロワーで開き、遷移を深くしない（REQ-NAV-02）。台帳に明記された操作（追加・編集・削除・実行・一括処理）は必ず操作可能に作る＝閲覧専用に倒さない（AC-NAV-05）。
- 表示状態は**5類型**（通常/読込中/計算中＋再試行/空/エラー）を全一覧・全詳細が持つ（REQ-SEC-06）。
- UI文言はハードコードせずラベル辞書経由で書く（REQ-NAV-07。将来の多言語化の拡張点）。
- コンテンツ幅は流体（fluid）。固定の max-width で中央寄せしない。
- レスポンシブ: 1024px 未満でサイドメニューはドロワー化（ハンバーガー開閉）。カード列は折返し（flex-wrap / auto-fit grid）で1カラムに退行する。閲覧系（ダッシュボード・分析・通知・履歴）はモバイル閲覧可、操作系はデスクトップ最適・モバイルは閲覧＋簡易承認まで（REQ-NAV-06）。Agent Officeはデスクトップ最適とし、モバイルでは通常ビューへ誘導する。
- Agent Officeビューにも同構成のサイドメニュー（暗色・ネオン）を置く: 「オフィス」＋第一階層項目＋本日のタスク＋オフィスLv.＋通常ビュー切替。項目クリックは該当部屋の室内詳細へ遷移する。

## 追補3 — Agent Office演出規約（§6.6 として取り込み）

プロトレビューで確定した演出の正本。「たのしさ」は臨場感の演出で出すが、**実データは常にHTML/CSSで描画**という素材規約（§6）を必ず守る。

### 俯瞰（ハブ）

- **1画面完結**: ヘッダー＋フロア＋ハブが100vhに収まるフレックス構成。スクロールさせない（極端に低いウィンドウのみ内部スクロールへ退避。フロア行は `min-height: min-content` で重なりを防ぐ）。
- **フロアは1面表示＋エレベーター昇降**: フロアを縦に並べない。エレベーターパネルのフロアボタンで移動し、扉が閉まる（0.7s）→ フロアインジケータ（シャフト光・移動方向▲▼）→ 扉が開く（合計約1.8s）。フロア構成・部屋割当・エレベーターのフロア表示は `office_layout.json` 駆動で、フロア数から生成する（REQ-AOUI-07）。**現行config v2.1.0 は正本初期構成準拠：7フロア（1部屋=1フロア＋ハブ、1F=01〜7F=07）・部屋7**。configの値をハードコードで再現しない。
- **配色**: 奇数階=ブルー系（scene_03を室内背景に）、偶数階=パープル系（scene_04）。フロアラベル・部屋枠・統計パネルの発光色も追従。
- **俯瞰は1部屋1キャラ**: 代表キャラのみ表示（優先度: エラー > 作業中 > 完了 > 待機。工程が進むと代表が入れ替わる）。全キャラは室内詳細で見せる。
- **部屋の臨場感レイヤー**: 室内背景（明るめ: 輝度+30%/彩度+12%）＋天井照明（scene_02）＋フロア色のライトコーン＋什器（green_rack / scene_01 を交互）＋足元ネオン。統計はモニター風パネル、キャラ名はネオン縁ネームプレート。
- **部屋ごとのホロ小物**: キーワード=タグクラウド / 制作=執筆ドキュメント / 分析=ミニチャート / 自動化=パイプライン / ナレッジ=書棚 / 設定=トグル / テクニカル=リンクグラフ。すべてHTML/CSS/SVG描画で、実データ連動へ差し替え可能な構造にする。

### 室内詳細（部屋クリックでズーム）※2026-07-09 中央壁面パネル構成へ改訂

- **入室はカットシーン**: 控えめフラッシュ → ブラー付きカメラ急接近 → 上下レターボックス → 光のスイープ → キャラが床から順次登場（0.14sずつ） → 右パネルスライドイン。
- **配置原則 — 背景アートは温存より情報配置を優先**: 「アートを見せるために中央を避ける」ことを禁じる。視線が集まる中央壁面には**ホロ投影パネル**（半透明＋スキャンライン＋光スイープ＋backdrop-blur）として情報を被せてよい。壁アートはパネル背後に透ければ演出として十分。サイドレールへの詰め込みは不可。
- **中央壁面ホロパネル**: ステージを縦フレックス（上=パネル／下=キャラ列）のフロー配置とし、絶対配置同士の衝突を構造的に排除する。パネルの構成順: ①状態連動ホロ小物 ②「エージェントの作業を詳しく見る」導線ボタン（Office詳細ページへ・対象ごと） ③統計タイル＋WORK LOG（横並びグリッド）。
- **右パネル構成**: 「何を見ますか？」（探索・ワークベンチ） → おすすめ、の2カードのみ（統計・WORK LOGは中央パネルへ移設済み）。
- **WORK LOGモニター**: 部屋固有の作業ログが約1.7秒間隔で流れる（直近5行・完了系は緑・スキャンライン付き）。文言はユーザー語彙（§6.5）で書き、本番イベントへ差し替え可能にする。
- **状態連動ホロ小物**: 「部屋でいま最も動きのあるペルソナ」の状態と連動。作業中=状態色の点滅＋光スイープ＋高速浮遊、完了=緑、エラー=赤、待機=グレー。
- **会話吹き出し**: 約5.2秒間隔でキャラ頭上にポップ（3.4秒で消滅）。セリフは状態連動＋部屋固有のひとことを混ぜる。2キャラの部屋では従キャラも時々発言。
- **ボタンの可視性**: 押せるもの=立体（グラデ＋影＋ホバー変化）、飾り=フラットタグ、で必ず差別化する（クリック可否が形状で分かること）。
- **BGMビジュアライザー**: 下部中央のガラス風ピルにイコライザー（装飾・実音声なし）。実BGMを載せる場合は初期ミュート必須。

### Office詳細ページ（深堀り・1ページ=1対象）※2026-07-09 新設

- **目的**: 「人間にはちょっと面倒・難しい作業をエージェントがこなしている」様子を見せる深堀り面。Officeビュー=実行状況の確認基盤（見守る・深堀り）、通常ビュー=選択の基盤（選ぶ・決める・承認）の役割分担の中で、Office側の"細かく見る"を担う。
- **1ページ=1対象**: ページの単位は1キーワード or 1記事 or 1承認案件 or 1学習パターン or 1監視対象。その対象の**全詳細データ＋「エージェントの分析」**をグリッドでぎっしり載せる（1グラフ=1ページの細切れは不可＝深堀りにならない）。
- **レイアウト**: 左=内部メニュー（対象の切替）／中央=データグリッド（縦ストレッチで100vhを充填。下端に空洞を残さない）／左下=担当エージェント（小さく・状態連動・吹き出しにワンメッセージ）。ヘッダーに「部屋へ戻る」。
- **ページ型は5種（2026-07-09 全7部屋に拡張）**、いずれも既存の型A/型B骨格を再利用して一貫性を保つ:
  - **型A メトリクスグリッド**（2列6カード）＝キーワードリサーチ／レポート分析（カード見出しをデータ駆動化して流用）。
  - **型B ドキュメント進行**（3fr:2fr・本文/工程/品質）＝コンテンツ制作。
  - **型C 承認差分**（型B骨格・左=変更差分 before→after縦ペア＋矢印／右上=実行条件＋予算バー／右下=安全ルール判定 ✓!✕）＝自動化オペレーション。NEXT ACTIONは該当承認を通常ビューのモーダルで開く。
  - **型D 学習知見**（型A骨格・学んだこと/根拠の実測値 before→after/効果の推移 適用時点マーカー・学習中は点線/反映先/確信度）＝ナレッジ。上昇=良いのトレンドは専用ヘルパーで描く。
  - **型E ステータス盤**（型A骨格・ステータス行/ヘルスゲージ SVG円弧/可視化 cells稼働格子・linkgraphリンクグラフ・cwv Core Web Vitals・ledgerクレジット内訳/監視ログ/影響・修正候補）＝設定／テクニカルSEO（共有）。
- **スクロール絶対禁止**: overflow-y / max-height を使わない。カラム溢れによるスクロールバー表示も違反。極小ウィンドウでは内容クリップを許容（デスクトップ最適=REQ-NAV-06）。**SVGカード（ゲージ・リンクグラフ・スパークライン）は `position:absolute; inset:0`（wrapper `position:relative; flex:1; min-height:0`）で描く**＝`width/height:100%` 直置きだとviewBoxのアスペクト比由来の固有min-heightがカードを押し上げ、SVGが2枚並ぶページで溢れる（2026-07-09 型Eで検出・是正）。
- **データは正本と同一**（REQ-AOUI-01）: 通常ビューのKW_ROWS・クエリ分析・成果物一覧と数値・状態・ストーリーを一致させる。未計測はプレースホルダで正直に示す。実行状態（再送待ち等）は通常ビューのstateと連動。
- **NEXT ACTION**: 決定操作は持たない。各ページ下部に「通常ビューで◯◯する」ボタンを1つ置き、該当の通常画面（キーワード選択・承認・タスク管理・成果物）へ引き渡す。
- **導線**: ①部屋の中央パネルの導線ボタン ②キャラクリック「何を見ますか？」内の「DETAIL — 詳しく見る」グループ（俯瞰からは部屋ズーム＋ページ表示まで一気に遷移） ③通常ビューS2「オフィスで詳しく見る」（選択中キーワードのページへ）・S3「オフィスでライブ編集を見る」。
- **全対象を個別深掘りできる「詳細エクスプローラ」（2026-07-09 拡張・キーワード/記事）**: keyword_research・traffic_report は代表数件の手書きでなく、正本（`KW_ROWS`/`KW_CLUSTER_DETAIL`/記事統合レコード `ARTICLES`）から**全キーワード・全記事の型Aページをデータ生成**（`buildKwPages()`/`buildArticlePages()`・`officePagesFor(rv)` で集約）。既存の作り込みページは `_kw`/`_slug` 一致で上書きマージし温存（`depth:'deep'`）、生成物は `depth:'auto'`。**Officeビュー=詳しさ優先**（通常ビュー=見やすさ優先）の役割分担を、1対象=全データの深掘りで担う。
  - **データ源泉は DataForSEO(市場・SERP)＋Search Console(自サイト実績)** を想定し、逆引き値を実APIで取れる形に揃える。基本データカードは**3×2の来歴段組み**: 上段 MARKET·DataForSEO（検索数/難易度/**AI Overview 出現・なし**）／下段 PERFORMANCE·Search Console 28日（クリック/表示回数/CTR）。**AI Overview(AIO)は必須表示**（MARKETセル＋SERP行＋分析文の3面）。CVは別ソース（自社CVポイント台帳）として混同しない。
  - **左サイド=関連度で引くナビ**（`relatedOf()` 単一関数＝サイドバー/関連カード/クロス動線が同一ソース）。2グループ「関連{キーワード|記事}」（現在＋同種Top3・クラスタ理由サブ行）＋「別の視点で見る」（キーワード⇄記事のクロス＝紫・1〜2件・**クリックで部屋跨ぎ切替**）。**最大6行・スクロール禁止を厳守**、あふれは「通常ビューで一覧」へ逃がす。非キーワード/記事の部屋は従来flat。表記ゆれはトークン包含一致で吸収。
  - 生成物と作り込みの**温度差はバッジ（好調/急落/学習元/未公開/注目・最大1）＋分析深度チップ（実データ精査/自動要約）で正直に**示し、均質偽装しない。部屋の入口列挙は注目度上位6件に絞る（`topOfficePages`）。

### 素材の運用実績（ASSET-MAPPING補足）

- **使用禁止**: `scene_05` / `scene_08` / `scene_ref_*`（数値・文言の焼き込みがあるため。§6の素材規約違反）。
- 動的に差し込む画像は `<img src>` ではなく **background-image** で描く（ブラウザの先読みがテンプレートの未解決プレースホルダを誤取得するため）。
- すべての演出は `prefers-reduced-motion: reduce` で自動停止する。

## 追補4 — 通常SaaSビューのビジュアルテーマ規約（§6.7 として取り込み）

コンセプト: **プロフェッショナル＆高級感、されど業務すぎずおしゃれに**。初心者にも使いやすい明快さを保つ。Agent Officeビュー（暗色ネオン）とは印象を明確に分ける。

### カラー — ブルー×シルバー・メタリック

- ベース背景はホワイト系グレー `#EDF0F5`（純白にしない）。カードは白 `#FFFFFF`＋枠 `#D5DEEB`。
- **濃色は左上に集める**: ヘッダーは左（濃紺 `#142850`）→右（明 `#2E5AA8`）、サイドメニューは上（濃紺）→下（明）へのグラデーション。ロゴのある左上コーナーが最も濃く、そこから光が広がる構図。
- プライマリはトークンのブルー系。ボタンはフラットでなく光沢グラデ `linear-gradient(180deg, #4A87F2, #2A63D4)`＋上辺インセットハイライト。アクティブ状態（セグメント・タブ・チップ）も同グラデ。
- **ゴールドはチャージ（課金）専用アクセント** `linear-gradient(180deg, #FFE9A8, #F0BE3D)`。他用途に使わない。
- **ステータス色は減彩度版を使う**（色の引き算）: 成功 `#339B7D`（濃 `#21725C`）/ 注意 `#B5893A`（濃 `#7C6230`）/ エラー `#D25B5B` / 強調パープル `#7E6BD9`。彩度の高い原色はOfficeビュー専用。
- テキストは `#16294B`（見出し）/ `#51637F`（補助）/ `#7A8BA6`（微弱）のブルーグレー階調。

### メタリックの表現

- 面のグラデよりも**光の線**で出す: ヘッダー上端のスペキュラーライン（白のグラデ1px）、全カード上辺の `inset 0 1px 0 #FFFFFF`。
- 影は**二層**を共通トークンに: `0 1px 2px rgba(23,43,77,.07), 0 10px 28px -14px rgba(23,43,77,.2)`（＋上辺インセット）。
- シルバーチップ（サイト切替等）は `linear-gradient(180deg, #FCFDFE, #EDF2F8 55%, #DFE7F2)`＋枠 `#C9D4E4`。

### 数値と密度

- 数値はすべて IBM Plex Mono（桁が揃う）。KPIは表示時にカウントアップ（約1秒・イーズアウト・reduced-motionでは即値）。
- KPIカードには小さなスパークライン（8点・淡ブルーグレー線＋現在値ドット）。
- 一覧はテーブル型＋ソート可能（列見出しにSVGチェブロン）。密度は「プロ向け管理画面寄り」。

### マイクロインタラクション

- 行の入場は25〜50msのスタッガ、KPIカードはホバーで1px浮上＋影深化、承認完了トーストはチェックが描画されるアニメ（stroke-dash）。
- アイコンはすべてSVG描画（ストローク1.8・角丸端点）。テキスト絵文字（✕ ▲ ● 等）は使わない。

### レイアウト補足

- サイドメニュー幅は両ビュー共通 **200px**（モード切替で幅を変えない）。ロゴブロックはヘッダーと同じ **56px** 固定で区切り線を揃える。
- 課金導線は常設: ヘッダーに残高＋チャージ（狭幅はチャージのみ）、ダッシュボードのクレジットカード（承認待ちより上に配置）、購入は3ステップモーダル（プラン選択→確認→完了・完了で全残高表示が即時更新）。
- ヘッダーには稼働中ジョブの進行（ジョブID＋工程名＋ミニプログレス）を常時表示する。
