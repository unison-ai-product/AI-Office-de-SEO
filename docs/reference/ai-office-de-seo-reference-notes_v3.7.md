# AI Office de SEO 参照ノート v3.7

本書は要求（L1）ではなく、設計の根拠となる参照資料である。出典を明示し、Google公式でない第三者情報は「非公式・要調整」と区別する。

> **利用境界**: §3以降の画面・アセット・部屋・ペルソナ数は旧モック制作時の在庫と配置案であり、現行製品の機能数、Agent数、LLM実行役数、部屋数を決める正本ではない。現行の業務能力はAgent要求・Agent Function Map、画面責務はScreen Inventory、遷移はScreen Flowを参照する。アセットは必要な能力を表現できる場合だけ再利用し、数を合わせるためにAgentや部屋を作らない。

## 1. Query Fan-out（公開ロジック）

`REQ-SRC-02`（Query Fanout）の設計根拠。Google AI Mode / AI Overviews の検索側の技術であり、本製品はその「網羅の考え方」を自サイトのコンテンツ網羅・サブクエリ被覆に応用する（Googleの内部実装の複製ではない）。

### 1.1 Google公式で確認できること

出典（一次情報）: AI Features and Your Website — https://developers.google.com/search/docs/appearance/ai-features

- AI Overviews と AI Mode は「query fan-out」技術を使う場合がある。これは、サブトピックとデータソースにまたがる複数の関連検索を発行して回答を組み立てる仕組みである。
- 回答生成中に、より多くの裏付けページを特定し、通常のウェブ検索より広く多様なリンクを提示しうる。
- AI Mode と AI Overviews は異なるモデル・技術を使うことがあり、提示される回答・リンクは変わりうる。
- 補足（Google発表・報道ベース）: 単一クエリを複数のサブクエリへ分解し、ライブウェブ・ナレッジグラフ・構造化/ショッピングデータ等を並列に取得して統合する。複雑・多面的なクエリで強く働き、単純な事実クエリ（例: 「スペインの首都」）では広く発動しない。Deep Search は1クエリで数十〜数百の背景検索を出しうる。

### 1.2 分解の考え方（公開情報の総合）

- クエリを エンティティ / 制約 / 時間参照 に解析し、各要素を狙うサブクエリを生成する。複雑度が発行サブクエリ数を左右する。
- サブクエリは、言い換え・関連意図・比較・エンティティ拡張・暗黙の意図などの角度を持つ。

### 1.3 第三者ヒューリスティック（非公式・要調整）

- 「8種類のサブクエリ」「複雑クエリで9〜11本」等の型・本数はSEO業界の推計であり、Google公式の数値ではない。
- 「トピカルオーソリティ」やカバー率の相関値（例: 主クエリ＋1サブクエリで引用率が上がる等）は第三者調査であり保証値ではない。
- 本製品では、これらを網羅の初期指標として扱い、L3で自社データにより較正する。

### 1.4 本製品への写像（REQ-SRC-02）

- Query Fanout Agentは、シードキーワード/GSCクエリを、facet（エンティティ・制約・意図・時間・比較・類語）別のサブクエリへ分解する。
- 各サブクエリを Source Pack（SERP/PAA/AIO/関連語、`REQ-PACK-07`）で取得し、サブトピック網羅（`REQ-PACK-09` comprehensiveness）へ接続する。
- 取得不可（AIO等）は捏造せずavailability理由を返す（`REQ-WPA-10`）。ダーククエリ（検索ボリューム0の関連サブクエリ）も網羅対象に含めうる。
