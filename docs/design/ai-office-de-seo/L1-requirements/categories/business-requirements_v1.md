# AI Office de SEO 業務要求

## 1. 責務

SEO業務がどのような段階を循環し、各段階で何を判断し、何を成果物として次段階へ渡すかを定義する。

本書の正本範囲は次のとおり。

- SEO戦略の設定から現状把握、調査、課題発見、計画、実行、公開、観測、評価、再計画までの業務ライフサイクル
- 各段階の開始条件、業務入力、判断、成果物、完了条件、戻り先
- 人が判断する箇所と自動運用へ委ねられる箇所
- 見送り、保留、差し戻し、停止、再開の業務上の扱い

本書には計算式、データ項目、画面、API、イベント、DB、外部連携方式を定義しない。それらは各分類の要求IDを参照する。

## 2. SEO業務ライフサイクル

`戦略設定 → 現状把握 → 市場・検索調査 → 課題・機会発見 → 施策計画 → 優先順位・配分決定 → 制作・改善 → 確認・公開 → 観測・評価 → 再計画`

このライフサイクルは一度で終了せず、Siteの運用期間中継続する。記事単位の小さな循環と、Site全体の月次循環を接続する。

## 3. ライフサイクル要求

### REQ-BUS-01 戦略設定

- 開始条件: 対象Siteと運用責任者が決まっている。
- 業務入力: 事業目的、商品・サービス、対象顧客、対象地域、ブランド方針、CV定義、SEO運用上の制約。
- 判断: 当該SiteでSEOが担う役割と、当月に重視する目的を決める。
- 成果物: Site戦略、対象顧客、重点テーマ、月次目的、禁止・保護方針。
- 完了条件: 運用責任者が内容を確認し、現状把握の評価軸として利用できる。
- 戻り先: 事業方針、商品、対象顧客、CV定義が変わった場合に再設定する。

### REQ-BUS-02 現状把握

- 開始条件: Site戦略が設定され、対象Siteの記事と計測対象を特定できる。
- 業務入力: 公開記事、サイト構造、獲得キーワード、順位、表示、クリック、CV、更新履歴、過去施策。
- 判断: 現在の流入、CV、情報充足、記事品質、サイト構造、計測可能性を把握する。
- 成果物: 記事棚卸し、キーワードと記事の対応、記事遍歴、計測欠損、初期課題一覧。
- 完了条件: 既知、未取得、取得不能を区別し、調査対象を決められる。
- 戻り先: 記事追加、公開、計測定義変更、外部接続変更時に差分更新する。

### REQ-BUS-03 市場・検索調査

- 開始条件: Site戦略と現状把握から調査対象が決まっている。
- 業務入力: 対象テーマ、検索需要、検索結果、AIO、広告面、競合、季節性、自Site実績。
- 判断: 検索市場の構造、競争、クリック獲得余地、ユーザーの問い、必要な信用性を把握する。
- 成果物: 市場観測、検索意図、競合差分、需要変化、調査の鮮度と確信度。
- 完了条件: 課題・機会を説明できる根拠が揃うか、根拠不足として明示される。
- 戻り先: 鮮度期限、順位急変、市場変化、追加調査要求で再調査する。

### REQ-BUS-04 課題・機会発見

- 開始条件: 現状把握と利用可能な調査結果がある。
- 業務入力: Site戦略、記事棚卸し、記事遍歴、市場観測、検索実績、CV実績。
- 判断: 新規情報需要、既存記事の不足・陳腐化・意図ずれ、重複、内部リンク不足、CV導線不足、保護対象を識別する。
- 成果物: 新規作成、リライト、統合、内部リンク、CTA改善、更新、保護、監視、見送りの候補。
- 完了条件: 各候補に対象、理由、期待する変化、根拠、反証条件がある。
- 戻り先: 根拠不足は調査へ、戦略不一致は戦略設定へ戻す。

### REQ-BUS-05 施策計画

- 開始条件: 課題・機会候補が作成されている。
- 業務入力: 候補、記事間依存、予算、実行能力、公開制約、直近変更、保護方針。
- 判断: 実施、保留、却下、見送りを決め、必要な作業と順序を組み立てる。
- 成果物: 月次施策計画と、対象・目的・変更範囲・確認条件を持つ実行単位。
- 完了条件: 実行対象、順序、予算枠、確認責任者、見送り理由が決まっている。
- 戻り先: 予算不足は配分決定へ、根拠不足は調査へ、対象競合は課題発見へ戻す。

### REQ-BUS-06 優先順位・配分決定

- 開始条件: 月次目的と施策候補がある。
- 業務入力: 月次目的、候補の価値・緊急性・確信度・費用・リスク・依存関係、実行可能量。
- 判断: 月次目的へ向かう傾向として、新規記事、リライト、統合、内部リンク、CTA、保護、監視へ実行枠を配分する。
- 成果物: 優先順位付き施策キューと月次配分。
- 完了条件: 実行可能量を超えず、達成保証ではなく方向性として説明できる。
- 戻り先: 月次目的変更時は実行済み施策を維持し、未実行分だけ再配分する。

### REQ-BUS-07 制作・改善

- 開始条件: 実行対象、目的、変更範囲、根拠、予算枠、確認条件が確定している。
- 業務入力: Site戦略、記事方針、対象記事または新規テーマ、調査根拠、品質・表現上の制約。
- 判断: 新規記事を制作するか、既存記事のどの範囲を変更するかを確定する。
- 成果物: 新規記事案、リライト案、統合案、内部リンク案、CTA改善案等の公開候補。
- 完了条件: 変更目的と変更内容が対応し、確認可能な状態になっている。
- 戻り先: 根拠不足は調査へ、方針不一致は計画へ、品質不合格は制作工程内で修正する。

### REQ-BUS-08 確認・公開

- 開始条件: 公開候補と確認条件が揃っている。
- 業務入力: 公開候補、変更差分、根拠、品質結果、公開予定、責任者。
- 判断: 承認、差し戻し、保留、公開中止を決める。
- 成果物: 確認記録、公開結果、公開日時、公開者、変更履歴。
- 完了条件: 公開成功または非公開判断が記録され、観測対象を特定できる。
- 業務規則: 新規Siteでは、本サービスで新規作成し、人が承認して公開成功した新規記事15件まで個別承認を必須とする。既存記事、外部作成記事、リライトは件数に含めない。
- 業務規則: 15件到達後、公開権限者が責任範囲へ同意した場合、新規記事を自動公開運用へ移行できる。
- 業務規則: リライトは既存公開内容を変更するため、新規記事の自動公開とは別に確認・復元条件を決める。
- 責任境界: 公開内容の最終判断と公開責任は公開者に帰属する。対外文言は法務レビューを受ける。

### REQ-BUS-09 観測・効果評価

- 開始条件: 施策が公開・適用され、評価対象と評価開始日を特定できる。
- 業務入力: 公開前後の順位、表示、クリック、獲得キーワード、CV、ページ遷移、記事状態、市場変化。
- 判断: 変化の有無、期待との一致、悪化、測定不能、評価継続を判断する。
- 成果物: 施策評価、記事遍歴、成功・失敗・不明の区分、追加観測または是正候補。
- 完了条件: 評価可能なものは結果を記録し、評価不能なものは不足データと再評価時期を記録する。
- 戻り先: 悪化は課題発見へ、測定不能は現状把握・計測整備へ、変化継続中は観測を継続する。

### REQ-BUS-10 再計画

- 開始条件: 月次期間が終了した、重要な評価結果が出た、または戦略・市場が変化した。
- 業務入力: 月次目標、実行施策、未実行候補、効果評価、費用、停止・失敗・見送り理由。
- 判断: 継続、強化、縮小、停止、再調査、戦略変更を決める。
- 成果物: 翌月の目的、施策配分、継続候補、停止候補、調査課題。
- 完了条件: 次周期の戦略設定または現状把握へ入力を渡せる。
- 業務原則: 順位、流入、CV、売上、工数削減を保証せず、実績がないものを擬似的に数値化しない。

### REQ-BUS-11 例外・停止・再開

- 対象: 根拠不足、計測不能、権限不足、予算不足、品質不合格、外部障害、公開失敗、好調記事への悪影響。
- 判断: 保留、差し戻し、見送り、手動切替、停止、再開条件設定を行う。
- 成果物: 発生段階、理由、影響対象、責任者、解除条件、次の業務行動。
- 業務原則: 見送りと観測継続を正式な判断とし、記事を増やすことだけを成果にしない。
- 業務原則: 自動運用中でも停止条件と責任境界を解除しない。

### REQ-BUS-12 運用責任

- Site運用責任者: 戦略、月次目的、予算、公開方針、自動運用方針を決める。
- SEO実務担当者: 調査、候補確認、計画、制作・改善、評価を行う。
- 公開権限者: 公開可否と自動公開への移行を決定する。
- 自社コンサルタント・運用担当者: 付与された顧客・Site・業務範囲内で支援する。
- サービス運営者: サービスの稼働、障害対応、契約上の提供範囲を担うが、SEO成果を保証しない。
- 対象外: 代理店運用、OEM、ホワイトラベル。

## 5. 受入条件

- [ ] AC-BUS-01: Site戦略と月次目的が現状把握・評価の基準として使用される。
- [ ] AC-BUS-02: 既知・未取得・取得不能を区別した現状把握が作成される。
- [ ] AC-BUS-03: 市場・検索調査に鮮度、根拠、確信度が付与される。
- [ ] AC-BUS-04: 新規作成以外にリライト、統合、リンク、CTA、保護、監視、見送りが候補になる。
- [ ] AC-BUS-05: 月次施策計画に実施・保留・却下・見送りと理由が記録される。
- [ ] AC-BUS-06: 月次目的から実行可能量内の方向性配分が作成され、達成保証として表示されない。
- [ ] AC-BUS-07: 制作・改善の成果物が目的、根拠、変更範囲と対応する。
- [ ] AC-BUS-08: 新規Siteの新規記事15件まで個別承認され、既存記事・外部記事・リライトが件数から除外される。
- [ ] AC-BUS-09: 施策評価が成功・失敗・不明・観測継続に区分される。
- [ ] AC-BUS-10: 評価結果と未実行候補が翌月の目的・配分へ戻される。
- [ ] AC-BUS-11: 例外発生時に段階、理由、影響、解除条件、次の行動が記録される。
- [ ] AC-BUS-12: 戦略、実務、公開、支援、サービス運営の責任者が区別される。
