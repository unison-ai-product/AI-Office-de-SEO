# AI Office de SEO 画面・操作要求

## 責務

画面の情報責務、表示状態、操作、入力、確認、遷移、権限別表示を定義する。

必須項目:

- 画面目的と対象Role
- 入力データと表示データ
- 通常、読込中、計算中、空、エラー、stale
- 作成、編集、採用、保留、却下、承認、取消
- 破壊的操作の確認
- レコメンド主導線と手動探索補助線
- 一覧上限、ページング、仮想化
- 画面間の文脈引き継ぎ

画面内で独自の業務判定・優先順位計算を行わない。ロジック要求の結果を表示する。

既存ソース: `ai-office-de-seo-navigation-ui-requirements_v3.7.md`、`ai-office-de-seo-agent-office-ui-requirements_v3.7.md`、L3画面台帳。

## 要求

### REQ-SCREEN-01 推薦ホーム

ログイン後の主導線は、Siteの目標、重要アラート、優先推薦、進行中ジョブ、承認待ち、予算状態をまとめた推薦ホームとする。自由検索・手動作成は補助操作として提供する。

### REQ-SCREEN-02 推薦カード

推薦ごとに「なぜ今か」「なぜこの対象か」「何を変えるか」「期待改善」「実行しない場合」「費用」「リスク」「鮮度」を短く表示し、詳細で使用データと根拠を確認できる。

### REQ-SCREEN-03 推薦操作

採用、編集して採用、保留、却下、一括採用を提供する。却下・保留は理由を記録でき、一括採用時も予算、権限、重複、好調記事保護、承認条件を項目ごとに検証する。

新規Siteでは、本システムで新規作成し、完成記事を人間承認後に公開成功した記事だけを15件まで進捗表示する。既存記事・外部記事・リライトは進捗へ含めない。到達前は新規記事の自動投稿設定を利用不能とし、到達後は同意書の版・要点・責任境界と自動投稿の対象範囲、予算、停止条件を確認して有効化できる。見出し構成確認はSite単位でON/OFFでき、ON時はOutlineで停止して見出しを編集・確定できる。

### REQ-SCREEN-04 非同期状態

長時間処理は画面を占有せず、受付、待機、実行、保留、承認待ち、完了、失敗、取消の状態と進捗を表示する。ユーザーは許可範囲で画面を離れ、後から状態確認、取消、再試行できる。

### REQ-SCREEN-11 Agent Officeによる待機体験

通常ビューでは業務結果と次の判断を簡潔に表示し、Agent Officeビューでは同じジョブ・イベント・状態をエージェントが働く様子として表現する。Officeビューの演出は実状態から導出し、処理を速く見せるための虚偽進捗を生成しない。

### REQ-SCREEN-05 表示状態

主要画面は通常、初回読込、部分読込、計算中、空、stale、権限不足、予算不足、外部連携切断、エラーの状態を区別する。空白または無限spinnerだけで状態を表現しない。

### REQ-SCREEN-06 組織・権限画面

顧客側管理者は組織階層、所属、Role、Scope、承認経路、予算配賦を確認・変更できる。変更前に影響対象と失われる権限を表示し、結果を監査履歴から確認できる。

### REQ-SCREEN-07 開発管理画面

内部権限者は機能公開、状態別UI、業務フロー、推薦、Provider、品質、ジョブ、障害、顧客支援を管理できる。一般ユーザー画面と明確に分離し、対象環境と代理操作中であることを常時表示する。

### REQ-SCREEN-08 権限とサーバー判定

画面は実行RoleとResource Scopeに応じて情報と操作を表示するが、非表示やdisabledを認可の正本にしない。直接APIを呼び出した場合も同一Permission判定で拒否する。

### REQ-SCREEN-09 文脈引継ぎ

推薦から詳細、Ticket、承認、ジョブ、公開結果、効果確認へ、tenant、site、対象、根拠、フィルターを引き継ぐ。戻る操作で一覧位置と選択状態を失わない。

### REQ-SCREEN-10 大量データ表示

記事、キーワード、推薦、ジョブ、監査等の一覧はサーバー側ページング、絞込み、並べ替えを使用し、全件を初期取得しない。件数と用途に応じて仮想化または段階読込を行う。

### REQ-SCREEN-12 文体設定

Site設定で、文末を「です・ます調／だ・である調」から選択し、文章表現を文語体／口語体の組合せで指定できる。個別Siteの記事から固有の言い回しを学習する設定をON/OFFできる状態で置く。ON時はサンプル記事10本の選定、学習対象、適用状態を表示し、10本未満は暫定プロファイルとして明示する。3か月ごとに見直し通知を表示し、再学習はユーザー操作で開始する。OFF時はSite由来の言い回しを使用せず、サンプル記事を要求しない。

### REQ-SCREEN-13 要監視キューと段階評価

急変対象は通常の推薦カードと区別して要監視キューへ表示し、急変内容、観測開始、1か月・3か月・6か月の確認期限、現在の状態を示す。ユーザー指定予定は継続し、システム予定は「3位以内の向上目的につきprotect/observeへ差し替え／低順位改善につき続行」の判定理由を表示する。公開・更新後のページには一次・二次・長期評価を分けて表示し、悪化時は復元候補とWPリビジョンまたはバックアップの利用可否を示す。復元はユーザー操作で実行する。

予測画面はSiteのGSCクリックが直近1か月で1,000件へ到達するまで数値予測をロックする。到達後も記事単位で予測可能・データ不足を分け、予測可能記事数、ロック記事数、不足理由を表示する。公開ページ評価では、割り当てたプライマリ＋セカンダリのキーワードクラスタと実際の獲得順位を対比する。

順位なしはリライト失敗ではなく、GSC／URL Inspectionのインデックス状態、確認日時、quota・availability、原因候補、確認箇所、ユーザー対応事項を表示する。SiteのOwner/Adminと記事担当者へ通知し、権限者が `未確認／確認済み／外部対応中／解消` を更新できる。解消は次回GSC確認で再検証し、未確認のまま自動解決扱いにしない。システムはサイト設定を自動修復しない。

CVなし単体をエラー表示せず、十分なクリック母数がある場合だけCVR評価を表示する。セカンダリ優位時は主従入れ替えではなく、業界別ロジック補正の再計算状態と根拠を表示する。

### REQ-SCREEN-14 業界・業種設定

Site設定で「業界／業種」の2階層を複数選択し、優先順を並べ替えられる。割合入力は要求しない。標準候補にない場合はユーザーが追加でき、追加値であることを識別できる。横断軸は対象顧客、共通課題、商品・サービス、地域、ファネルの構造化項目と補足自由記述を提供する。

未設定時はキーワードとサイト情報から推定した業界／業種、横断軸、confidence、根拠、精度非保証を表示し、ユーザーが確認・修正できる。現在適用中の業界prior、global fallback、横断軸、Site固有補正への移行状態、参照versionを確認できる。設定変更前に未実行推薦・配分の再計算範囲を表示し、実行済み履歴が変更されないことを確認できる。順位悪化リスクを持つSite固有補正は自動適用せず、差分、対象、根拠を表示して承認を求める。

記事詳細では主担当の業界／業種1組と関連分類を複数表示・編集できる。ユーザーが推定分類を確定した後は確定値を正本として表示し、推定との乖離は上書きせず変更候補として示す。

複数業界のSiteでは、優先方式を「ユーザー指定／自動」から選択できる。ユーザー指定では優先順を並べ、自動では算出根拠と配分を表示する。分類変更時は、ユーザー指定予定が維持されることと、目的不一致で要確認へ戻るシステム自動予約を区別して表示する。

### REQ-SCREEN-15 記事制作・リライト実行面

新規記事の実行面は、Recommendation／手動起動、Intake結果、Preflight見積、Research Brief、Outline Contract、Section Brief、生成進捗、Quality Gate、限定Repair、WordPress下書き、プレビュー、承認・Automation判定、公開結果を同一相関IDで追跡できる。

リライト実行面は、原因、Edit Plan、対象section、許可operation、変更上限、保持対象、変更前後差分、title/meta、見出し、CTA、内部リンク、品質・保護結果、復元点、費用を表示する。変更対象外のsectionが維持されたことを確認できる。部分リライト・全文再生成ともWordPress下書きへ送り、リスクと復元可否を確認してユーザーが更新を承認する。全文再生成は高リスク操作として影響範囲と追加確認を伴って提供する。

専用バックアップが利用できない場合はWordPressリビジョンへの依存と復元制約を表示し、上位プランのバックアップ・拡張保持を「安心保証」として提示できる。ただし順位、流入、CV等の成果保証と誤認させない。

AI Office内でユーザーが本文・見出しを修正した場合はその変更を保護し、変更箇所を再QAする。記事装飾は本文生成と分離して最終プレビュー前に実行する。装飾済みWordPress下書きのPreview URLを正規プレビューとして表示し、埋込みが認証・CSP等で利用できない場合はWordPressの新規タブで開く。

標準WorkflowではWordPress送信後の本文をAI Officeから編集・上書きしない。WordPress内編集オプション、AI生成版との差分表示、変更履歴の取得は後続機能として表示上も分離し、初期リリースの必須画面に含めない。

装飾設定では、Siteから検出したテーマ、標準・独自ブロック、ショートコード、CSS classを候補として表示し、Preview、依存関係、利用可否を確認してユーザーが採用対象を選択できる。未選択または互換性未確認の独自パーツを自動使用しない。

装飾学習の候補は言い回し学習と別画面・別設定で表示し、頻出ブロック、配色、CTA、画像比率、装飾パターンからユーザーが採用対象を選択できる。

初期リリースの画像送信状態はアイキャッチについて、生成、最適化、メディア登録、Media ID／URL取得、featured media割当を表示する。本文中画像の生成・配置設定は後続versionとして初期画面に含めない。

画像生成調整画面は、Site既定と記事単位overrideを分け、目的、トーン、画風、構図、色、明暗、人物、文字入れ、比率、配置、枚数、禁止要素、参照画像を選択・記述できる。WordPressメディアまたはURLから解析対象を選び、抽出したStyle Featureを個別に採用・除外してからProfileへ保存できる。

生成前に想定画像数、size、quality、予測クレジット、cache再利用可否を表示する。生成後は採用、再生成、調整して再生成、記事から除外、Media登録を選べる。新規生成を伴う再生成は追加クレジット対象として表示する。

アイキャッチPattern Editorは生成前に、背景、被写体、文字、ロゴ等の領域をcanvas上で選択し、位置、比率、余白、重なり、表示、固定・可変、配色、トーンを編集できる。ロゴは配置領域と外周余白を設定できる。記事タイトル、カテゴリ、キーワード等の差込slotを配置し、Patternの保存、複製、version作成、undo／redo、既定指定を提供する。

Patternごとにバリエーション許容度を「固定」「制御」「自由度高」から選択し、制御型では変更を許す属性と範囲を指定できる。生成前に固定される要素と毎回変わる可能性がある要素を区別して表示する。

Pattern編集と簡易ワイヤーフレーム表示ではクレジットを消費しない。実画像の確認が必要な場合だけ「GPT Image 2でテスト生成」を実行し、実行前に予測費用と生成回数を表示する。記事生成時は選択済みPatternと記事slotを自動結合する。

出力sizeは接続中CMSのCapabilityから取得したfeatured media／thumbnail要件だけを候補表示する。CMS要件外のSNS・広告用sizeを初期画面へ追加しない。画像の採否と公開判断はユーザー操作およびAutomation Policyに従い、人物、商品、実績等の内容分類だけで個別確認を追加しない。自動投稿の画像警告は技術的不成立・ユーザー設定不一致による停止とadvisoryを分け、承認済みPatternの軽微な見た目差だけで停止しない。

WordPress下書き投入後の「プレビュー」は別成果物を生成する工程ではなく、当該下書きを実テーマで表示確認する任意操作とする。WordPress Adapterから取得できた「WordPressで編集」「実表示をプレビュー」をAI Officeの確認画面に表示し、確認後は同じ画面から承認・公開または差し戻しへ進める。最初の15記事で必須となるのは完成記事への承認記録であって、Preview URLを必ず開いた操作ログではない。

Site接続・記事確認画面は `REQ-INT-05` のCompatibility Matrixと `REQ-LOGIC-08` の出力方式判定を表示し、UI独自の互換性判定・縮退順序を持たない。Site全体の検出状態と記事単位の実効Capabilityを分け、選択経路、利用可能操作、失われる機能、縮退理由、元記事との関係を表示する。既存記事の更新が保留でも、分析・Recommendation・別成果生成を継続できる操作状態を示す。

WordPressリビジョンも専用バックアップもない場合は、復元不能であることを強調表示し、権限者の同意後に限りリライトまたは全文再生成を続行できる。

hard gate、予算、承認、外部接続、Repair未収束による保留は理由、解除条件、担当、期限、次の操作を表示する。hard gate成果の手動公開は、警告・未解消項目の再確認と版付き同意の二段階確認を要求する。中断・再開時は完了済みstage、残作業、追加見積を表示し、サービス障害による再開とユーザー希望の有償再生成を区別する。

### REQ-SCREEN-16 プラン機能の可視化とロック

現契約で利用できない上位機能は完全に隠さず、名称、得られる効果、必要な入力または出力の例を判別できる範囲で表示する。機密情報、他顧客データ、実処理結果と誤認する疑似データは表示しない。

ロック状態は、ぼかし、Preview、説明カード等で上位機能の価値を理解できるようにし、対象プラン、追加費用、解放後に増える範囲、現在プランで可能な代替操作を示す。閲覧用のぼかし解除やDOM・API直接呼出しによって機能を実行できないよう、利用可否はサーバー側のEntitlementで強制する。製品障害、設定不備、権限不足、データ不足を有料ロックとして表示しない。

### REQ-SCREEN-17 Capacity・自動構築表示

Site設定および契約・利用画面に、管理記事数、キーワード・Query数、保存容量、画像・バックアップ、当月取込量、計算量、同時処理等のCapacity Dimensionごとの使用量、上限、利用率、予測到達日を表示する。集計遅延と最終更新時刻を示し、異なるDimensionを単一残量へ混在させない。

soft limitでは削減・archive、処理延期、Plan変更、購入可能な場合の追加容量を比較表示する。Entry／StandardはPremiumへの変更を主提案とし、Premium／Enterpriseは追加容量購入も選択可能にする。hard limitでは制限対象、既存データへの影響、再開条件を表示する。

初回取込が分割実行されるSiteは「自動構築期間」として、進捗、現在工程、取得済み範囲、利用可能な機能、一部制限中の機能と理由、概算完了時期、失敗・再試行状態を表示する。全構築完了まで画面全体を利用不能にせず、成立した機能から段階的に開放する。

## 受入条件

- [ ] AC-L1-SCREEN-01: ログイン後に最優先の推薦・承認・異常を確認できる。

- [ ] AC-L1-SCREEN-03: 採否・保留理由と一括操作の個別検証結果が記録される。
- [ ] AC-L1-SCREEN-04: 長時間ジョブ中も他画面を操作し後から復帰できる。
- [ ] AC-L1-SCREEN-05: 読込、空、stale、権限不足、連携切断、エラーを識別できる。
- [ ] AC-L1-SCREEN-06: 組織・権限変更前に影響差分を確認できる。
- [ ] AC-L1-SCREEN-07: 内部管理面で対象環境・顧客・代理操作状態を誤認しない。
- [ ] AC-L1-SCREEN-08: UI操作可否とAPI認可の結果が一致する。
- [ ] AC-L1-SCREEN-09: 推薦から効果確認まで対象と根拠が維持される。
- [ ] AC-L1-SCREEN-10: 大量一覧が全件初期取得を行わない。
- [ ] AC-L1-SCREEN-11: Agent Officeビューの表示状態が実ジョブ・イベントと一致する。
- [ ] AC-L1-SCREEN-12: 文体の組合せと個別Site言い回し学習のON/OFFを設定でき、ON時だけサンプル記事10本を使用し、10本未満は暫定状態を確認できる。
- [ ] AC-L1-SCREEN-13: 急変対象が通常推薦と分離され、1か月・3か月・6か月評価の状態と既存予定の継続を区別できる。
- [ ] AC-L1-SCREEN-14: Siteへ業界／業種の2階層を複数設定・追加でき、複数設定時は横断軸を明記し、適用中の業界priorとSite固有補正の状態を確認できる。

- [ ] AC-L1-SCREEN-17: Capacityの使用量・上限・到達予測と、自動構築期間の進捗・利用可能機能・制限理由・完了見込みを確認できる。
