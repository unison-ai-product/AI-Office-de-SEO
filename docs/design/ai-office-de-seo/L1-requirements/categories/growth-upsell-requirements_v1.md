# AI Office de SEO 成長・アップセル要求

## 1. 責務  ［REQ-UPSELL-01］

顧客の利用状況と成果に基づき、上位プラン、追加クレジット、サイト追加、コンサルティング、完全委託等を適切な時期に提案する条件、表示、計測、抑制を定義する。

アップセルは売上最大化だけを目的とせず、現在の契約では顧客の目標達成・安定運用・コスト効率が不足する場合に、根拠を示して選択肢を提示する。

## 2. 提案対象  ［REQ-UPSELL-02］

| 提案 | 主な適用条件 |
|---|---|
| 追加クレジット | 残高不足、予定ジョブ、失効・繰越を考慮して不足見込み |
| データ・バックアップ容量 | Siteの保存上限への接近または到達。Entry／StandardにはPremiumを提示し、Premium／Enterpriseには追加容量商品を提示 |
| リライト安心保証 | 部分リライト・全文再生成の実行前に、専用バックアップ、保持延長、復元支援を含む上位プランを提示 |
| 上位システムプラン | サイト数、ユーザー数、処理量、監査、SLA、連携機能が現在上限へ接近 |
| サイト追加 | 管理対象外サイトがあり、同一組織で運用効果が見込める |
| コンサルティング | 戦略判断、優先順位、競合分析、経営KPI連動に人的支援が必要 |
| 完全委託 | 承認・対応滞留、運用時間不足、継続実行の人的負担が高い |
| 年間契約 | 継続利用実績があり、契約条件と割引の差を明示できる |

## 3. 判定入力  ［REQ-UPSELL-03］

- プラン上限と利用率
- クレジット残高、消費速度、予定ジョブ、失効予定
- recommendation queueと採用済み実行予定
- サイト数、ユーザー数、記事数、キーワード数、処理量
- 承認・保留・サポートの滞留
- SLA、監査、権限、外部連携の必要性
- 原価、見積精度、顧客粗利
- 顧客が設定した目標と現在の不足

SEO成果が上がらないことだけを上位プラン提案の根拠にしない。製品不具合、設定不備、データ不足を課金で解決させない。

## 4. 判定ロジック  ［REQ-UPSELL-04］

- `capacity_need`: 現プラン上限への接近度。
- `execution_need`: 採用済み・高優先recommendationを実行するための不足。
- `governance_need`: SLA、監査、権限、承認、セキュリティ要件の不足。
- `support_need`: 顧客自身での運用が滞る度合い。
- `economic_fit`: 追加購入と上位プランの総額・原価・利用見込みの適合。
- `confidence`: 入力期間、利用実績、予定の確度。

提案は上記成分を表示し、単一の不透明な販売スコアだけで決定しない。

Capacity Dimensionのsoft limit到達時は、Entry／Standardへ追加容量だけを販売せず、Premiumへの変更によって増える容量、機能、品質、バックアップ、契約期間と総額を提示する。Premium／EnterpriseはPlan変更に加えて追加容量を購入可能にし、どちらが利用見込みと総額に適するか比較する。hard limit到達後も既存データを人質にせず、閲覧、export、削減・archive、Plan変更または追加容量購入へ到達できるようにする。

## 5. 提案抑制  ［REQ-UPSELL-05］

- 契約直後、却下直後、障害中、請求争議中、解約手続中は抑制する。
- 同一提案にcooldownと表示回数上限を設ける。
- 現プランで代替できる操作、設定変更、不要ジョブ取消、軽量実行がある場合は先に提示する。
- 利用不足の顧客へ上位プランを提案せず、活用支援またはダウングレードを含む適正化を提示する。
- 緊急性を偽るカウントダウン、根拠のない残数表示、事前選択、解約妨害を禁止する。

## 6. 表示  ［REQ-UPSELL-06］

提案には次を表示する。

- なぜ提案されたか
- 現在の契約と利用状況
- 変更後に増えるもの・増えないもの
- 月額、初期費用、クレジット、税、日割り、適用日
- 現プランのままの場合と他の選択肢
- 解約・ダウングレード条件
- 自動適用されないこと

プラン変更・追加購入はOwnerまたは認可されたRoleだけが確定できる。

## 7. レコメンド・コストとの接続  ［REQ-UPSELL-07］

- コンテンツrecommendationの実行不足から追加クレジットを提案する場合、採用済みまたは高confidence候補の必要量だけを見積もる。
- 未採用候補をすべて実行する前提で過大なクレジットを提案しない。
- リライトの書き換えリスクとWordPressリビジョンの制約を事実として表示し、専用バックアップ・保持延長・復元支援を「安心保証」として提案できる。
- 安心保証は復元可能性と支援範囲を販売するものであり、順位、流入、CV、売上等のSEO成果保証として表示しない。
- 追加購入、上位プラン、実行延期、候補削減を同じ比較に出す。
- 顧客支払額だけでなく、提供原価と想定利用率を確認し、採算不能な提案を自動表示しない。

## 8. 営業・サポート連携  ［REQ-UPSELL-08］

- 高額、Enterprise、コンサル、完全委託はセルフ確定ではなく相談予約へ接続できる。
- 営業へ渡す情報は提案根拠、利用集計、顧客が共有を許可した目標に限定し、記事本文・プロンプト・秘密情報を含めない。
- サポート問い合わせを無条件に営業リード化しない。営業連携の目的と範囲を明示する。
- 標準導線は製品内FAQ・Help記事を根拠とするFAQチャットとし、回答根拠、対象version、解決可否、有人引継ぎ条件を表示する。
- FAQチャットは全Planへ提供する。Premiumは有人問い合わせを通常queueより優先し、営業日基準で1営業日以内の初回回答を運用目標とする。Enterpriseは問い合わせ時間帯、severity別初動、連絡経路、復旧・報告、未達時の扱いを個別SLAで定める。
- 個別のSEO戦略相談、記事内容の人間review、WordPress修正代行、運用代行は有償支援とする。製品不具合、課金誤り、接続障害の切分け・是正を有償支援へ誘導しない。

## 9. 計測  ［REQ-UPSELL-09］

- 提案対象数、表示数、詳細閲覧、相談、購入、却下
- 提案種別別conversion
- 提案後の利用率、継続率、粗利、返金、ダウングレード
- 誤提案、苦情、表示抑制、cooldown
- 提案根拠別の精度
- アップセル後に増えた実利用と未利用枠

購入率だけで最適化せず、継続利用、適正利用、粗利、苦情、解約を併せて評価する。

## 10. 受入条件

- [ ] AC-L1-UPSELL-01: 提案がcapacity/execution/governance/support/economic fitへ分解される。
- [ ] AC-L1-UPSELL-02: 障害・争議・解約中と却下cooldown中に提案されない。
- [ ] AC-L1-UPSELL-03: 現プラン内の代替策とダウングレードを含む適正化が先に比較される。
- [ ] AC-L1-UPSELL-04: 未採用recommendationを全実行する過大見積にならない。
- [ ] AC-L1-UPSELL-05: 料金、適用日、日割り、増える機能、増えない機能が表示される。
- [ ] AC-L1-UPSELL-06: 購入・プラン変更が権限者の明示操作なしに確定しない。
- [ ] AC-L1-UPSELL-07: 同一提案の回数上限とcooldownが機能する。
- [ ] AC-L1-UPSELL-08: 全PlanのFAQチャットから根拠付き回答または適切な有人引継ぎへ到達でき、Premiumの優先対応とEnterpriseの個別SLAを区別し、営業連携へ本文・秘密情報が渡らない。
- [ ] AC-L1-UPSELL-09: 購入率だけでなく継続・利用・粗利・苦情・解約が計測される。
- [ ] AC-L1-UPSELL-10: 製品不具合や設定不備を上位契約で解決させない。
- [ ] AC-L1-UPSELL-11: 容量接近時にEntry／StandardへPremiumを提示し、Premium／EnterpriseではPlan変更と追加容量を比較して権限者が選択できる。
