# AI Office de SEO 画面・UI要求 v3.7

## 分類別正本への移行

画面・操作は `categories/screen-operation-requirements_v1.md`、情報理解・文言・アクセシビリティは `categories/design-experience-requirements_v1.md` を現在の正本とする。本書の `REQ-NAV-*` はNavigation固有の詳細として維持し、同じ状態・判定を再定義しない。

## 1. ユーザー向け第一階層  ［REQ-NAV-01］

ユーザー向けGlobal Sidebarは、以下に制限する。

1. ダッシュボード
2. キーワード管理
3. コンテンツ作成
4. オートメーション
5. サイトページ管理
6. ナレッジ管理
7. 設定

第一階層に、内部実装用語を表示してはならない。

表示禁止語の例:

- Pack
- Ticket
- Source Pack
- Prompt Pack
- Dynamic Post Schema
- GSC Data Mart
- DataForSEO
- Prompt Cache
- Token Tracker
- Sandbox
- Schema Registry

## 2. 通常ビュー  ［REQ-NAV-02］

通常ビューは、標準SaaS型の実務UIである。テーブル、グラフ、フォーム、詳細レポート、記事プレビュー、承認、投稿予約などを広く扱う。

グローバルUI要素: 通知センター（`REQ-PRODUCT-11`）と進行中ジョブのインジケータ（`REQ-AGENT-10`の停止/再開導線を含む）は、第一階層メニューではなくヘッダー等の常設グローバル領域に置く。これらは`REQ-NAV-01`の第一階層7項目の制限に数えない（メニュー項目を増やさない）。

情報構造（サイドメニュー＋タブ）: 通常ビューは**左サイドメニュー**に第一階層7項目（`REQ-NAV-01`）とグローバル要素を常設し、各画面内の第二階層は**タブ**で表現する（例: 設定→サイト/メンバー/連携/通知/データ利用/契約/請求）。第三階層（個別レコードの詳細・編集）はパネル/ドロワーで開き、遷移を深くしない。開発管理者コンソールも同型（サイドメニュー=ADM-S1〜S12＋画面内タブ、`REQ-ADM-01`）。各画面は表示に加えて**その画面で可能な操作（追加・編集・削除・実行・選択）を要求として明記**し、閲覧専用に倒さない。

## 3. Agent Officeビュー  ［REQ-NAV-03］

Agent Officeビューは、同じ機能を異なる問い合わせ方式で見せる体験レイヤーである。

- オフィスが前面に表示される。
- ユーザーはエージェントや部署に声をかける。
- 「どれを見ますか？」という選択肢が出る。
- 選択すると、画面1枚を占有する大きな詳細ビューが開く。
- 詳細ビューは通常ビューのタブ/パネルと対応しており、切替が容易である。

Agent Officeビューは、通常ビューと別の業務正本や権限体系を増やすものではない。通常ビューと同じTask・Agent・処理event・成果Projection・Domain Commandを使い、部屋、Agent、設備から成果、根拠、条件、配分、設定、Taskを玄人向けに詳細分析・操作する。定型会話は選択式、自由文は必要時だけLLMを使い、型付きProposalと確認を経て共通Commandへ渡す。通常ビューは同じ成果の要約と簡単操作を担う。

## 5. UI素材方針  ［REQ-NAV-05］

画像として使うのは、背景、キャラクター、部屋、装飾、アイコンに限定する。テキスト、数値、表、グラフ、フォーム、Task History、ボタンはアクセシブルなWeb UIとして描画する。製品要求はReact等の特定フレームワークへ固定せず、採用技術はGate A-4と実装計画で決める。

## 6. レスポンシブ方針  ［REQ-NAV-06］

初期リリースはdesktop標準とし、mobileでの業務完結、簡易承認、Agent Office操作を必須範囲に含めない。狭いviewportでも契約・接続等の重要情報を失わない最低限の表示崩れ防止は行うが、初期受入でmobile業務機能を約束しない。後続versionではAgent Office Chatをmobileの主導線とし、通知、確認、簡易なデータ説明、修正指示、Task状態確認を提供する。長文編集、詳細設定、画像Pattern編集、複雑なGraph操作はdesktopへ引き継ぐ。ブレークポイント・寸法はデザイントークン（Gate A-4）に置く。

## 7. 国際化方針（i18n）  ［REQ-NAV-07］

初期のUI言語は日本語のみ。ただしUI文言はコードへハードコードせず外部化し（表示ラベルレジストリ`REQ-ADM-11`と同型の仕組み）、通貨・日付・数値のロケール処理を分離して、将来の多言語化を実装変更なしの拡張点として確保する。**（2026-07 追記: プロト実装で本拡張点を行使し、日本語／English を提供。言語選択はヘッダーではなく設定画面「表示言語」に置き、`REQ-NAV-09` のレジストリ機構で差し替える。記事本文・キーワード等のデータは翻訳対象外。`Design.md §6.4` と整合。）**


## 8. アクセシビリティ品質床  ［REQ-NAV-08］

Gate A-4（デザイントークン）の「品質床」記述を要求として正本化する（Gate A-4は実装既定側、本要求がトレースの正本）。

- キーボード到達性: 主要行動（生成起動・承認・保留対応・通知確認、`REQ-UJ-01`の2遷移対象）はキーボードのみで到達・実行できる。フォーカスリングは常に可視（Gate A-4トークン準拠）。
- コントラスト: テキスト・操作要素はWCAG AA相当を目安とする（両テーマ。準拠レベルの正式確定と検証ツールはD台帳で決定）。
- モーション配慮: `prefers-reduced-motion` を尊重し、pulse/glow・キャラアニメーションを停止する（Agent Officeビュー含む）。
- 支援技術: 操作要素はラベルを持ち、意味を運ぶ画像はalt相当を持つ。テキスト・数値の画像焼き込み禁止（`REQ-NAV-05`）はスクリーンリーダー可読性の前提を兼ねる。
- 代替経路: 装飾性の高いAgent Officeビューが唯一の経路にならないこと——全操作は通常ビューで完結できる（`REQ-AOUI-01`の同一詳細コンポーネント原則が構造的に保証）。
- 検証: 自動チェック（コントラスト・ラベル欠落）はプロト受入（PT-Z）とCIの対象。準拠レベル実数・ツール選定はD-28。

## 9. UIテキストレジストリ（文言の運用差し替え）  ［REQ-NAV-09］

`REQ-NAV-07`の「外部化」を運用機構として確定する。ユーザー面の表示文言は、**コード変更・デプロイなしで差し替え可能**なレジストリで管理する。

- 対象: 画面ラベル・タブ名・ボタン・空状態/完了状態の案内文・エラー/警告/確認ダイアログ文言・オンボーディング文言・in-app通知テンプレート（メール文面は`REQ-PRODUCT-21`の同一Catalog機構）。**法務文言（同意書・利用規約）は対象外**＝`REQ-PRODUCT-09`の同意版管理に従う（自由差し替えを許さない）。
- 機構: key→文言のCatalogとして版管理し、編集・公開はADM-S8の統制（`REQ-ADM-10`: draft→Preview→Validate→Approve→Publish）。版のactivateで全画面に反映する。管理面ラベルレジストリ（`REQ-ADM-11`）と同一基盤・別名前空間（ui.text.*）とし、エージェントへのPack注入経路（`REQ-PACK-04`の`catalog.*`）とは混ぜない。
- 2層フォールバック: リリース同梱のベース文言（ja）＋レジストリのオーバーライド層。キー未定義時はベース文言へ、それも無い場合のみキーを表示し、欠落は観測（カバレッジ計測、`REQ-ADM-04`）へ記録する（silent failureの禁止。ユーザー面では「ラベル未登録」印は出さず、欠落可視化は管理側で行う）。
- プレースホルダ: 変数は名前付き（例: `{credit_amount}` `{site_name}`）。文言側の変数欠落・不一致はレジストリValidateで検出し、実行時欠落は空文字にせずキー名表示＋観測記録とする。
- 一貫性の検証: 同一キーは全画面で単一文言（訳語の単一ソース＝`REQ-ADM-11`と同旨）。Validateで禁止語（内部用語・model/provider名、`REQ-BILL-03`/`REQ-NAV-01`）の混入を機械検査する。
- 多言語拡張: ロケールはキー体系を共有し文言セットの追加のみで拡張（`REQ-NAV-07`）。
- 型付きアクセサ生成（関数→日本語）: レジストリからビルド時に**型付きアクセサ（関数/定数）を自動生成**し、コード側は関数参照のみを書く（日本語リテラルを書かない）。存在しないキーの参照・変数シグネチャ不一致は**ビルドエラー**とし、実行時欠落をコンパイル時に前倒しする。生成物はレジストリ版とハッシュで対応づけ、手編集しない。
- 日本語リテラル検査（外部化の機械強制）: UIコードに日本語文字列リテラルが存在しないことをCI lintで検査する（テスト・許可リストの例外は明示管理）。「外部化」を宣言でなく構造で保証する。
- 逆引き（日本語→キー）: 表示文言からキーを検索する逆引きを管理画面（ADM-S8）と開発ツールに備える（完全一致＋部分一致・候補リスト返却）。逆引きの実用性のため、**同一名前空間内の文言完全一致の重複はValidateで警告**する。
- 共通術語辞書基盤: 内部キー（event_type・gate・config・エラーコード等）の訳語は、管理面ラベルレジストリ（`REQ-ADM-11`）と本レジストリが**同一の術語テーブルを参照**し、ユーザー面/管理面/通知/監査で同じキーの訳語が揺れないこと。
