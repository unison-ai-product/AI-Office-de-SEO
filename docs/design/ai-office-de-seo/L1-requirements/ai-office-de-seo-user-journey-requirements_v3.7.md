# AI Office de SEO ユーザー行動要件

ユーザー（および開発管理者）が「何を、どの画面列で、どう成し遂げるか」を要件として固定する。画面台帳（AOS-L3-SCREEN-INVENTORY / ADMIN-SCREEN-INVENTORY）が「点」の要求、本書が「線」の要求であり、画面遷移図（AOS-L3-SCREEN-FLOW）は本書から導出する。各ステップは画面ID（S1〜S7 / W1〜W10 / ADM-S1〜S12）と既存要求を参照し、本書は新機能を発明しない。

## 1. 行動原則  ［REQ-UJ-01］

すべてのジャーニーに適用する横断原則（数値は初期値・要調整、`REQ-ADM-09`）。

- 到達性: 主要行動（生成起動・承認・保留対応・通知確認）は第一階層から2遷移以内。通知（W7）からの対処完了は2遷移以内（`REQ-PRODUCT-11`の通知→対象遷移）。
- 行き止まり禁止: すべての画面・空状態・完了状態は「次アクション」を提示する（空のキーワードマップ→手動追加/シード展開の開始導線、生成完了→プレビュー/承認導線）。
- 文脈引き継ぎ: 分析画面で見つけた対象は、その場から実行へ移せる（S2/S5→S3のプリセット引き継ぎ、`REQ-NAV-04`）。実行前の警告（アサイン競合・鮮度・予算）はクレジット消費前に画面で提示する（`REQ-KGA-14` / `REQ-KGA-18` / `REQ-SEC-12`）。
- 非同期原則: 生成・取得はジョブとしてバックグラウンド実行され、ユーザーは画面に拘束されない。進捗はW5・通知で追える（`REQ-AGENT-01`）。
- 安全な操作: 破壊的・不可逆操作（削除・Kill Switch・解約・公開）は確認と理由/影響の提示を伴う。未保存編集の離脱は保護する。権限外の操作は原則非表示とし、文脈上必要な場合のみ無効表示＋必要Roleを示す（強制は常にサーバー側、`REQ-PRODUCT-08`）。

## 2. 初期導入ジャーニー  ［REQ-UJ-02］

対象Role: Owner（コンサル同席、`REQ-PRODUCT-09`）。完了条件: 初回記事が承認・公開され、GSCデータ取り込みが開始されている。

1. 登録・同意（W9: 最終責任・データ利用同意）→ テナント/サイト作成（S7）
2. Google接続（GSC、`REQ-PRODUCT-05`）／WPプラグイン導入・接続（`REQ-WPA-01`。プラグイン側UIは対象外）→ 接続状態の確認（S7）
3. サンプル記事10本の選定→文体学習（S6、`REQ-PACK-16`）。10本未満は暫定プロファイルの明示（`REQ-WPA-06`）
4. 戦略入力: ターゲット軸・主張軸（S6、`REQ-PRODUCT-12`）
5. キーワードマップ生成の確認・手動追加（S2、`REQ-KGA-03`）
6. 初回生成（S2→S3引き継ぎ起動）→ 構成確認 → 承認（W4）→ 公開（`REQ-WPA-04`）
- 分岐: 接続失敗→再認可導線（`REQ-SEC-09`）。GSC反映は2〜3日遅延がある旨を表示（`REQ-KGA-11`）。

## 3. 日常運用ループ  ［REQ-UJ-03］

対象Role: Editor以上。完了条件: 未対応の承認・保留・アラートがゼロになる（日次目安）。

1. 入口はダッシュボード（S1）または通知センター（W7）
2. 承認待ち→W4で個別/一括承認・差し戻し ／ 保留（hard gate・予算・競合）→W3/W5で対応（要望追加・再実行・キャンセル、`REQ-AGENT-10`）
3. 今日のおすすめ→採用/却下（S1、feedbackへ記録`REQ-KGA-13`）
4. アラート（カニバリ・重複・繰り延べ）→W7から対象画面へ2遷移以内で対処
5. 変動サマリ（急変・アルゴ更新・SERP変動・ウォッチリスト変化）を確認し対応要否を判断。変動期間中はリライト保留ガードに従う（`REQ-KGA-20`）
- 分岐: Kill Switch作動中はW8バナーから状態確認。残高低下通知→S7クレジットへ。

## 4. キーワード戦略ジャーニー  ［REQ-UJ-04］

対象Role: Editor以上。完了条件: 未カバー象限・昇格候補・未割当バックログが判断済み（採用/却下/保留）になる。

1. S2でマップ確認→属性フィルター（ターゲット/業界/intent/YMYL）で絞り込み（`REQ-KGA-13`）
2. ギャップマトリクスで未カバー象限を特定→価値スコア順に候補確認（`REQ-KGA-17`）
3. 手動追加・シード展開で不足を補充（`REQ-KGA-03`）→分類・アサイン整理（`REQ-KGA-14`）
4. 昇格キュー・起点別候補（ニュース/動画需要）を採用/却下（`REQ-KGA-16`/`REQ-KGA-18`）
5. 採用分は選択→生成起動（S3へ引き継ぎ。複数は「おまかせ」一括投入、`REQ-BILL-11`）
6. トポロジープランナーで幹→枝→葉の配置・生成順序（CVに近い順）・リンク再調整キューを確定（`REQ-KGA-19`）

## 5. 生成〜公開ジャーニー  ［REQ-UJ-05］

対象Role: Editor以上（承認はOwner/Adminまたは承認権限者）。完了条件: 公開完了通知の受領（または明示キャンセル）。

1. 起点選択（S3: キーワード/ニュース/動画需要。S2等からの引き継ぎ時はプリセット、`REQ-KGA-18`）
2. 実行オプション（今すぐ/おまかせ。鮮度highはinteractive既定・注意表示）→Preflight見積→開始（`REQ-SEC-12`）
3. 進捗確認（W5: 13状態。停止/再開/キャンセル可、`REQ-AGENT-10`）
4. 構成・QA確認（W3: 記事タイプ・見出しフロー表示、gates合否、カスタム影響帰属）
5. hard gate保留→対応（要望追加・再実行/キャンセル）。通過→プレビュー承認（W4）
6. 公開/予約（S4）→ 完了通知（W7）→ 効果はS5で追跡
- 分岐: 予算超過→追加承認（`REQ-SEC-12`）。TTL失効後の再開→再ウォーム費の再見積提示。

## 6. リライト運用ジャーニー  ［REQ-UJ-06］

対象Role: Editor以上。完了条件: 差分適用が承認され、改善前後比較の追跡が開始される。

1. S5でリライト候補・原因解析（Query Drift/カニバリ/価値スコア、`REQ-RWR-06`）を確認
2. 候補からリライト起動（S3引き継ぎ）→ 差分プレビュー（W2、`REQ-RWR-04`）
3. 適用の確定/差し戻し（理由入力）→ 承認→反映（`REQ-WPA-04`）
4. 28日比較で効果確認（S5）。内部リンク候補・オーファンもここで採用/却下（`REQ-KGA-09`）
5. リライトブリーフ（落としたクエリ・追加候補・競合見出し差分・AIO状況）を根拠に再構成する（`REQ-RWR-08`）。好調記事は保護フラグ・要因（CV・滞在・スクロール）を確認し、直接変更でなく波及リンク強化を優先する（`REQ-RWR-08`/`REQ-WPA-11`）

## 7. 例外・緊急ジャーニー  ［REQ-UJ-07］

対象Role: Owner/Admin中心。完了条件: 各例外が定義済みの終端（解消・キャンセル・解約完了）に到達する。

- 再認可要求（通知→S7連携→再認可、`REQ-SEC-09`）
- 緊急停止（W8: Kill Switch作動→進行中ジョブ安全停止・予約保留戻し→解除、`REQ-DUR-04`）
- 支払い失敗（通知→S7請求=Customer Portal→復旧、`REQ-BILL-08`）
- 解約・退会（S7契約→オフボーディング申請→エクスポート/削除、`REQ-SEC-10`）
- 中断ジョブの保留期限超過→自動キャンセル通知→必要なら新ジョブ（`REQ-AGENT-10`）
- 解決しない事象→サポートパネル（W10）: AI一次応答→未解決はエスカレーション→チケット追跡（`REQ-PRODUCT-22`）

## 8. 開発管理者の運用ジャーニー  ［REQ-UJ-08］

完了条件: 日次=アラート/乖離が判断済み、変更=統制フロー完了、障害=インシデントクローズ。

- 日次: ADM-S1（golden signals・アラートack）→ ADM-S4（原価乖離・キャッシュヒット床・マッチ率）→ 必要ならADM-S7で較正（影響プレビュー→承認）
- 変更（Pack/辞書/価格）: ADM-S8/S2でdraft→Preview/影響確認→Validate→Approve→Publish（`REQ-ADM-10`/`REQ-BILL-10`）→ 結果をADM-S4で追跡
- ネットワーク学習提案: ADM-S7/S8の承認キューで採否（`REQ-PRODUCT-13`）
- 障害: ADM-S1起票→ADM-S6でトレース→（必要なら）ADM-S10でFlag/Kill Switch→復旧→クローズ（`REQ-ADM-07`）
- 顧客調査: ADM-S9なりすまし（read-only・記録）→ ADM-S5監査ログ

## 9. 月次プランニング・ジャーニー  ［REQ-UJ-09］

対象Role: Owner/Admin（計画）＋Editor（実行）。完了条件: 月末に実績・乖離要因が確認され、翌月計画が確定している。

1. 月初: 目標設定（S1プランニングタブ）→推奨配分の確認・調整（`REQ-PRODUCT-17`）
2. トポロジープランナーで強化カテゴリ・コア記事・生成順序を確定（S2、`REQ-KGA-19`）
3. 日次: UJ-03のループ＋変動サマリ確認（急変・アルゴ・季節・ウォッチ、`REQ-KGA-20`）
4. 週次: 進捗 vs 予測レンジの確認→配分の微調整
5. 月末: 実績・乖離要因の確認→翌月計画へ引き継ぎ

## 10. 受入との接続

各ジャーニーはAC-UJ-01〜09で検証する（AOS-L1-ACCEPTANCE-TRACE）。画面遷移図（AOS-L3-SCREEN-FLOW）は本書のステップ列と1:1で対応し、遷移図にない遷移をジャーニーが要求しないこと・ジャーニーにない行き止まりを遷移図が作らないことを相互検証する。
